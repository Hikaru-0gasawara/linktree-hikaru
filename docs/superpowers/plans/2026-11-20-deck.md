# Deck, Portfolio Card and Critters Everywhere — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single TCG card into a scroll-leafed deck (Hikaru + Portfolio), refresh Hikaru's card content, show the cards as a scrolling page in plain mode, add a reset button, a touch focus mode, and critters (with Creeper and Zombie) in both modes.

**Architecture:** Cards share one markup pattern (`.deck-slot > .tcg-card > .card.face-front + .face-back`) that is layout-transparent in plain mode. A new pure module `site/deck.js` maps deck progress `p` to each card's pose; the DOM layer reads `p` from a native scroll-snap track and writes transforms. `site/tcg-dom.js` becomes a per-card controller.

**Tech Stack:** HTML, CSS, vanilla ES modules, `node --test`. No dependencies, no build.

**Spec:** `docs/superpowers/specs/2026-11-20-deck-design.md` (extends `2026-11-20-tcg-card-design.md` and `2026-11-19-linktree-design.md`). Read all three.

- Colours only from `:root` tokens in `site/styles.css`; gold only for: Play, HUD brackets, panel/section labels, active language, résumé marker, focus ring, card border/frame, active TCG switch. Square corners on all chrome; card corners are pixel steps.

### Task 2: Deck pose math

**Files:** Create `site/deck.js`, `tests/deck.test.mjs`.

**Interfaces — Produces:**
- `deckScale(vw, vh) = Math.min((vw - 96) / 460, (vh - 160) / 642, 1.1)`.
- `progressFrom(scroll, stop) -> number` = `scroll / stop`, clamped to `[0, n-1]` by a second arg `n`: signature `progressFrom(scroll, stop, n)`.
- `poseFor(i, p, reduced = false) -> { x, y, s, rz, ry, shade, z, opacity }` for card `i` at progress `p`. `x`, `y` in card widths (multiply by 460 px in CSS space), `s` scale, `rz`/`ry` degrees, `shade` 0–1 (darken overlay), `z` integer stacking (higher on top), `opacity` 0–1. With `d = i - p`:
  - `d = 0`: `{x:0, y:0, s:1, rz:0, ry:0, shade:0, opacity:1}`, highest `z`.
  - `-1 ≤ d < 0` (leaving left), `u = -d`: `x = -0.62u`, `y = -0.04·sin(πu)` (slight upward arc), `s = 1 - 0.14u`, `rz = -6u`, `ry = 0`, `shade = 0.35u`.
  - `d < -1` (passed stack), `k = -d - 1`: `x = -0.62 - 0.035k`, `y = 0.012k`, `s = 0.86 - 0.02k`, `rz = -6 - 1.5k`, `ry = 0`, `shade = min(0.35 + 0.1k, 0.6)`; `opacity = 0` when `k > 2`, else 1.
  - `0 < d ≤ 1` (coming from the pile): `x = 0.58d`, `y = 0.02d`, `s = 1 - 0.14d`, `rz = 0`, `ry = 180d`, `shade = 0.2d`.
  - `d > 1` (pile), `k = d - 1`: `x = 0.58 + 0.03k`, `y = 0.02 + 0.015k`, `s = 0.86 - 0.02k`, `rz = 0`, `ry = 180`, `shade = min(0.2 + 0.08k, 0.5)`; `opacity = 0` when `k > 3`, else 1.
  - `z = 100 - Math.round(Math.abs(d) * 10)`.
  - `reduced = true`: same `x`, `s`, `shade`, `opacity`, `z`; `y = 0`, `rz = 0`, and `ry = d > 0.5 ? 180 : 0` (no gradual flip).
- `unwindWeight(i, p) -> number` = `Math.min(Math.abs(i - p), 1)`: how far card `i`'s user rotation must be blended back to upright (0 at the centre, 1 when fully off-centre).

- [ ] **Step 1: Failing tests** `tests/deck.test.mjs`: the exact pose at `d = 0, ±1, 0.5, -0.5, 2, -2, 5, -5` (use a `near` helper, 1e-9); continuity at `d = ±1` (values just inside and outside differ by < 1e-6 in every field); `opacity` 0 beyond the limits; `z` strictly decreases with `|d|`; reduced variant at `d = 0.4` and `0.6` (ry 0 / 180, rz 0, y 0); `deckScale(1440, 900)` = `min(1344/460, 740/642, 1.1)`, `deckScale(390, 844)` = `294/460`; `progressFrom(1500, 1000, 2)` = 1 (clamped), `progressFrom(500, 1000, 2)` = 0.5, `progressFrom(-20, 1000, 2)` = 0; `unwindWeight(1, 0.3)` = 0.7, `unwindWeight(0, 2)` = 1.

# TCG Card Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A switchable "TCG" mode that shows the existing linktree as one 3D trading card you can rotate freely, with a painted forest on its back; on by default on computers, off on phones.

**Architecture:** Pure orientation/settings logic in a new ES module `site/tcg.js` (unit-tested). Markup wraps the existing `main.card` in a stage → fit → card structure that is layout-transparent (`display: contents`) when the mode is off, so the plain linktree is untouched. A small DOM module wires pointer drag, inertia, flip and keyboard to the pure functions.

**Tech Stack:** HTML, CSS, vanilla ES modules, Node ≥22 `node --test`. No dependencies, no build.

**Spec:** `docs/superpowers/specs/2026-11-20-tcg-card-design.md` (extends `docs/superpowers/specs/2026-11-19-linktree-design.md`). Read both.

## Global Constraints

- Static site in `site/`, no runtime/CDN dependencies, no build step. Tests: `npm test` (`node --test tests/`).
- Colours only from the `:root` tokens in `site/styles.css`. Gold (`--gold`) only for: Play, HUD brackets, panel labels, active language, résumé marker, focus ring, the card border/frame, the active TCG switch.
- Square corners on all chrome; the card's corners are pixel steps (clip-path, 2 steps of 4px), never `border-radius`.
- With the mode off the page must look and behave exactly as before this plan (same layout, same entrance, same links). The back art must not be fetched while off.
- Card design size 460×642 px; `scale = min((innerWidth − 32) / 460, (innerHeight − 160) / 642, 1.25)`.
- Default mode: stored `localStorage.tcg` (`'1'`/`'0'`) wins; else `matchMedia('(hover: hover) and (pointer: fine)').matches`. Storage access always in try/catch.
- Drag: 0.5°/px, starts after 6px; inertia friction 0.94 per 16.7ms, stop below 0.02°/frame; flip 500ms with `--ease` (`cubic-bezier(.2,.7,.2,1)`); arrow keys 15°.
- Reduced motion: no inertia, instant flip, opacity-only entrance; dragging still rotates.
- Tap targets ≥ 44px; visible gold focus ring; hover styles only inside `@media (hover: hover) and (pointer: fine)`.
- Strings in PT/EN/JA live in `STRINGS` in `site/i18n.js`; every key in all three languages.

## Review Focus

- A drag that ends over a link must not open it; a tap (<6px movement) on a link must open it, with mouse and with touch. (Task 3 browser check.)
- Mode off on a phone-sized viewport: page identical to before, and the network panel shows no `card-back.webp` request. (Task 2 browser check.)
- JA at 1280×720 in card mode: the face content fits inside the card with no overflow or broken words. (Task 2 browser check.)
- Rotating far (several full turns in diagonal directions) keeps the card undistorted: quaternion stays normalized. (Task 1 test `stays unit after many drags`.)
- `localStorage` throwing: mode falls back to the pointer default and the switch still works for the session. (Task 1 test.)

**Files:**

**Interfaces:**
- Produces (named exports of `site/tcg.js`), quaternions are arrays `[x, y, z, w]`:
  - `CARD_W = 460`, `CARD_H = 642`
  - `loadTcg(storage, fineHover: boolean) -> boolean`, `saveTcg(storage, on: boolean) -> void` (key `'tcg'`, values `'1'`/`'0'`, errors ignored, invalid stored values ignored)
  - `fitScale(vw: number, vh: number) -> number`
  - `IDENTITY` (`[0,0,0,1]`), `quatMul(a, b)`, `quatNormalize(q)`, `slerp(a, b, t)`
  - `quatFromDrag(dx, dy, degPerPx = 0.5)`: rotation of `hypot(dx,dy)*degPerPx` degrees about the axis `(-dy, dx, 0)` normalized (CSS space: +x right, +y down, +z toward viewer; so a rightward drag is a positive turn about +Y and moves the face's centre right, a downward drag is a turn about −X and moves it down); `[0,0,0,1]` when dx = dy = 0
  - `applyDrag(q, dx, dy, degPerPx = 0.5) -> q'` = `quatNormalize(quatMul(quatFromDrag(dx, dy, degPerPx), q))`
  - `quatToCss(q) -> string` like `rotate3d(0, 1, 0, 180deg)`; identity → `rotate3d(0, 1, 0, 0deg)`
  - `facingFront(q) -> boolean` (front normal `(0,0,1)` rotated by `q` has z > 0)
  - `flipTarget(q) -> q'`: `[0,1,0,0]` (180° about Y) when `facingFront(q)`, else `IDENTITY`
- Produces (new `STRINGS` keys in pt/en/ja): `tcgLabel` ("Modo carta" / "Card mode" / "カードモード"), `flip` ("Virar" / "Flip" / "裏返す"), `cardLabel` ("Cartão de Hikaru Ogasawara" / "Hikaru Ogasawara's card" / "小笠原ヒカルのカード").
